# AshGo — Existing Feature Matrix

**Classification**
- ✅ Verified in code and coherent
- 🧪 Implemented, not adequately tested
- 🟡 Partially implemented
- ❌ Broken or potentially unsafe
- ❓ Unclear without runtime or backend evidence

"Verified in code" means the logic is coherent on reading. It does **not** mean it was observed working on a device.

The **Decision** column is a recommendation. Final decisions are recorded in PRODUCT_DECISIONS.md after owner review.

| # | Feature | Files | Current behaviour | Defects | Class | Decision | Migration notes | Acceptance criteria (v2) |
|---|---|---|---|---|---|---|---|---|
| 1 | Role selection (traveler / receiver) | `MainActivity.kt` `RoleSelectionScreen` | Stores the role in SharedPreferences. Routes to one of two dashboards. | Not identity. Either phone can pick either role. Both phones can pick the same role. The role is asymmetric, so the receiver can't share location or raise SOS. | ❌ (as security) | **Replace** with symmetric pairing. Both members can share, check in and raise SOS. Roles become optional presentation only. | Map the old role to an initial member slot during the first v2 launch, so existing data stays readable. | Two installs complete pairing. A third install cannot read or write pair data (rules test). |
| 2 | Location sharing (`TrackingService`) | `TrackingService.kt`, dashboard switch | Fused HIGH_ACCURACY fix every 2–5 s, overwriting `tracking/current_trip`. Notification says "shared securely". | Battery-heavy cadence. No accuracy, battery or paused fields. Restart after swipe-away is likely blocked on Android 14. Client timestamps. GPS-off check only at toggle time. | 🧪 | **Redesign**. Adaptive cadence: about 15 s on a trip, about 2–5 min idle. Server timestamp, accuracy, battery %, explicit `sharing: live/paused/off`. | Keep writing the legacy `tracking/current_trip` during the transition, so an un-updated partner still sees data. | The partner sees age, accuracy and a paused state. Stopping sharing never triggers "signal lost". Sharing is visible in the persistent notification. |
| 3 | Live map | `ReceiverScreen.kt` | osmdroid MAPNIK tiles, traveler marker, destination marker, status pill. | Fake initial coordinate. "Live" shown with no data. Recentres constantly. No OSM attribution (a tile-policy violation). Can't see your own location. osmdroid is archived. | ❌ | **Redesign UI, keep osmdroid for v2.0**. Re-evaluate MapLibre + OpenFreeMap later (PRODUCT_DECISIONS D-7). | None (UI only). | No marker until real data exists. Attribution visible. User can pan freely, with a "recentre" button. Stale data is drawn faded with its age. |
| 4 | Destination + arrival | `ReceiverScreen.kt` long-press; `TrackingService` geofence | The receiver long-presses the map to set a "Safe Zone". The traveler's service writes `arrived` within 100 m. | Only the receiver can set it. Arrival is surfaced only while the receiver's map is open. No ETA or expected time. No overdue handling. | 🟡 | **Replace with Trips** (see opportunities O-4 and O-5): the traveler or the partner sets the destination, with an optional "expect me by" time. Arrival triggers an automatic check-in. | Read the legacy `tracking/destination` once and convert it to a trip. | Arrival creates a check-in event that the partner's background service shows as a notification. |
| 5 | Dead-signal detection | `ReceiverService.kt`, `ReceiverScreen.kt` | Alarm tone plus notification if the last fix is over 5 minutes old. | False alarm after a deliberate stop. Cannot tell "phone offline" from "app killed" from "GPS lost". Alarm at max volume. | ❌ | **Redesign as presence** using `.info/connected` and `onDisconnect`, a heartbeat, and a paused state. Raise a gentle (non-alarm) notification only during an active trip. | — | Pausing shows "Paused" and nothing more. A stale trip shows "Last update 7 min ago · phone went offline at …". |
| 6 | SOS button | `MainActivity.kt` `DashboardScreen` | Long-press pushes `{isSosActive:true}`. Long-press again cancels. Toast. | No state machine. The toast claims success with no evidence. Anyone can cancel. Screens disagree about whether SOS is active. Traveler only. | ❌ | **Redesign** (O-1): hold-to-arm with a 3 s visible countdown and a cancel option. Explicit states. Either member can raise SOS. | New `pairs/{id}/sos/{eventId}` with server time and actor UID. Keep reading legacy `alerts`, but no longer write to it. | Every state in SECURITY_PRIVACY_AUDIT §3 is visible. A duplicate raise within an active SOS is a no-op. |
| 7 | SOS SMS | `TrackingService.sendEmergencySms` | Sent by the traveler's tracking service when it observes a new alert within 60 s. | Not sent if sharing is off. Can send 0,0 coordinates. Single-part send of a UCS-2 message (likely to fail). No result tracking. Hardcoded name. | ❌ | **Rewrite**: the phone that raises SOS sends the SMS itself, via `divideMessage` + `sendMultipartTextMessage` with sent and delivery intents. The text says "location unavailable" or "location from N min ago". Explain carrier charges. | Contacts stay in local storage. Migrate the `emergency_contacts_v2` JSON into a typed store. | A fake SMS sender in unit tests sees one dispatch per contact per SOS. The UI shows a per-contact result. |
| 8 | Emergency contacts | `DashboardScreen` sheets | Picker via `READ_CONTACTS`. Saved as JSON in prefs. | Logic in the composable. Needs the contacts permission unnecessarily. No way to send a test message. | 🧪 | **Retain and refactor**. Pick the phone row via `Phone.CONTENT_TYPE` (no permission needed). Add an optional "send a test message" with explicit consent. | Read both existing pref keys. | Contacts survive the upgrade. No `READ_CONTACTS` requested. |
| 9 | SOS widget | `SosWidgetProvider.kt` | One tap pushes an alert. | Accidental activation. No feedback. Spoofable broadcast. Write may be lost without `goAsync`. | ❌ | **Redesign**: tapping opens the full-screen SOS hold screen (over the lock screen). A 3 s hold there raises SOS through the same use case as the in-app button (D-6). | The widget ID stays the same; only behaviour changes. | A tap alone never sends. Releasing before 3 s sends nothing. |
| 10 | Volume-key SOS (accessibility) | `SosAccessibilityService.kt` | Holding Volume-Down for 3 s triggers SOS. | Collides with normal volume use. Blocked by "restricted settings" on sideloaded installs. Over-broad event mask. | ❌ | **Remove** (or defer to a P2 experiment with a distinct gesture). Replace with a Quick Settings tile plus the widget (O-10). | Remove the service declaration. Users who enabled it lose it, so release notes must say so. | — |
| 11 | Lock-screen SOS action | `TrackingService` notification | One tap on "TRIGGER SOS". | One tap, no confirmation. | ❌ | **Redesign**: the action opens the SOS hold screen. | — | Same as the widget. |
| 12 | Chat (text) | `TravelerChatScreen.kt`, `ReceiverScreen.kt` | Last 50 messages. `isFromTraveler` flag. | Spoofable sender. No send state. Possible double-send on fast taps. Chat notifications never show (missing channel). Duplicate code in two screens. | 🧪 / ❌ (notifications) | **Retain, rebuild** on a `ChatRepository`: `senderUid`, server timestamp, sending/sent/failed states, client-generated message ID for idempotency. | 13 | Photo / selfie in chat | `TravelerChatScreen.kt` | Camera preview bitmap → 600 px JPEG q50 → Base64 in the message. Traveler only. | Encoding runs in the UI. Base64 bloat (+33%). No size guard. | 🟡 | **Retain within ₹0**: encode off the main thread, max 1024 px, about 120 KB cap, stored in a separate `media/{id}` node so message lists stay small. Either member can send. Shorter retention for photos. | Old inline `imageBase64` keeps rendering. | A photo over 150 KB is rejected before upload. The chat list download doesn't include photo bytes. |
| 14 | Profile photo + display name | `AppDrawer.kt` | Full-res JPEG q40 → Base64 at `users/{role}`. | Multi-MB payloads. Decoded every recomposition. Listener leak. A "wrong default name" hack. | ❌ | **Redesign**: 256 px avatar, under 30 KB, stored per member. Names come from profiles; no hardcoded defaults. | Import the existing photo and name once, downscaled. | Avatar payload ≤ 30 KB. |
| 15 | Thunder (buzz) | chat screens, both services, `DashboardScreen` | Writes a timestamp. The receiver plays a max-volume alarm tone if the timestamp is under 10 s old. | Clock skew. No rate limit. | ❌ | **Redesign as "Nudge"** (O-8): an event with server timestamp and type (thinking of you / call me when free / are you OK?). Normal notification channel; respects Do Not Disturb. | 16 | Fake call | `DashboardScreen` | Plays an audio file in an in-app mini-player. | Not a call. | 17 | Unread badge | dashboards | `ChildEventListener` plus a SharedPreferences `last_read`. | Two implementations. | 20 | Auto-updater | `AutoUpdater.kt`, `MainActivity` | Listens to `app_config`. Downloads using the token. | Token exposure (S2). No integrity check. Debug-signed.
